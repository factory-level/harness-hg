The copy is always the one that rots

One version pin had quietly reached three copies across two languages. The fix was not discipline, and it was not a checklist. It was making the second copy fail the build.

The requirement is easy to state and unpleasant to satisfy: a clean server has to become a working deployment through a process that is documented, repeatable and pinned, and the same process has to produce the same result on the replacement server after the first one is destroyed. Scattered defaults cannot promise that. One file can.

So I went looking for where versions actually lived. The Argo CD version had reached three copies.

Not through carelessness, which is the interesting part. Each copy had been added by someone — me — solving a genuine local problem at a moment when reaching for the existing constant was inconvenient. Three reasonable decisions, one rotting system.

The copy is always the one that rots. Never the original.

Discipline was never going to work

I could have written "keep these in sync" into a contributing guide. Every project has that sentence somewhere and it does not work, because the moment the rule gets broken is exactly the moment following it is most annoying: you are three layers into something else and the constant lives in the wrong language.

What shipped instead: every version a bootstrap resolves lives in one committed file. Host binaries, each with its checksum, and the control-plane chart pins. The CLI imports it. The bootstrap program imports it. And a test greps both source trees and fails the build on any second literal copy of a pin.

Adding a version to a source file breaks the build, by design. That last sentence is the whole trick: the rule is not documented, it is enforced, and it is enforced at the cheapest possible moment, before the copy has a chance to drift far enough to matter.

What it bought

A bootstrap that installs only what the file resolves. A read-only preflight first, then checksummed installs of the unprivileged tools and the cluster itself, from a vendored upstream installer whose own digest is recorded, never curl | sh of a script that can change under you. A recovery that reaches for somebody else's URL at three in the morning depends on somebody else's uptime.

What it cost

  • Release channels are deliberately not built. The surface reports what resolves; it promotes nothing. That is a named cut, not an oversight.
  • Binaries are still fetched from their vendors at bootstrap time, checksummed rather than mirrored, so a genuinely offline bootstrap is not possible.
  • Some monitoring pins still sit in template YAML outside the manifest. The gaps page keeps that row rather than letting me round it off.
  • The remote path has no automated rehearsal yet. Its first real run will be its first real run.
  • Where sudo needs a password, the cluster install stops and prints the command for a human instead of escalating. Automation does not get further than the operator granted.

Five costs for one file. I would rather write them down than discover them.
