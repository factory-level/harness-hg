Fleet Canvas

See the whole fleet.

One canvas draws the working fleet, and you read it without reading a label: shape says what a thing is, colour says who owns it, and paper marks the one thing a person wrote.

Why it matters

A directory of records is reviewable, not glanceable.

A fleet described in Git is diffable and reversible — but nobody sees a fleet by reading a directory. The canvas is the product surface over the declarations: who is deployed, what each agent ships, which human approves what, and where the one hand-written note is warning you about something.

The canvas reads authoritative systems and never becomes one. It draws what Git and the cluster say; changing the fleet still means changing the record.

Shape means kind. Colour means ownership. Material means authorship.

— the canvas grammar

How it fits

From records to a board.

  1. 01

    The records declare what exists.

    Agents, tools, people, groups and events are all declarations in Git.

  2. 02

    Nexus compiles them into a canvas.

    The dashboard plugin renders each declaration as an object in a shared visual grammar.

  3. 03

    You read it, and act through Git.

    The board is a view. The pull request is still the door.
