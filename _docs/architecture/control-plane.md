# Control plane — as built

The `control-plane/` root as it actually stands. The desired state is the `control-plane/`
section of [`../design/platform.md`](../design/platform.md) (one directory per platform-owned
component, [ADR 0163](../adr/0163-control-plane-root.md)); the diff is the gap list.

## What exists

- **Fifteen component directories plus the plane convention**: `alert-router`, `alertmanager`,
  `argocd`, `dex-sso`, `event-router`, `external-secrets`, `fleet-dashboard`, `grafana`, `loki`,
  `monitoring`, `nexus`, `observability`, `prometheus`, `tunnel`, `wiki`, and `planes.yaml`.
  Every directory carries a README naming its purpose, machinery, and signals.
- **Who actually holds a chart**: `monitoring`, `observability`, `fleet-dashboard`, `loki`,
  `wiki` (chart + image), `event-router` (chart + image), and `nexus` each own `chart/`;
  `alert-router` owns `lib/` — a Helm *library* whose consumers commit regenerated copies via
  `infra/scripts/sync-alerting-lib.sh` (subchart copies live inside the monitoring and
  fleet-dashboard charts). The other seven (`grafana`, `prometheus`, `alertmanager`, `argocd`,
  `dex-sso`, `external-secrets`, `tunnel`) are README-only: they deploy through other machinery
  — kube-prometheus-stack values, the Pulumi components, the shared tunnel — and the directory
  is where their ownership and signals are written down.
- **`planes.yaml`** — the plane convention *as data* (#660,
  [ADR 0164](../adr/0164-plane-separation.md)): the two label keys, the control-plane
  namespaces, and the prefix rules that derive workload namespaces (`hermes-`, `ag-eve-`).
  `hg validate` reads it (`cli/src/validate/command.ts` via `cli/src/platform/planes.ts`), and
  the plane-label tests pin it from both sides (`cli/tests/planes.test.ts`,
  `plugin/tests/test_plane_labels.py`). A new control-plane namespace declares itself here or
  nothing recognizes it.
- **The chart-boundary gate** (#659, [ADR 0163](../adr/0163-control-plane-root.md)): every
  `Chart.yaml` in the repo must be declared in `infra/scripts/chart-boundary.yaml` with a class
  (`control-plane`, `library`, `harness`, `test-fixture`, `subchart-copy`, `compat-copy` — and
  `application` is deliberately not a class at all), each class has exactly one allowed root,
  and an undeclared cross-component reference fails. `infra/scripts/check-chart-boundary.py`
  runs in `make test` (`chart-boundary` target) and proves it bites via `--self-test` over
  `examples/invalid-chart-boundary/`. `infra/charts/` was deleted 2026-08-26 after
  the destination repo synced (the [ADR 0160](../adr/0160-harness-chart-migration.md) step-3 PR).
- **`nexus/` is the installable UI unit**: `manifest.json`, the committed `dist/` (built from
  `nexus-ui/` and byte-compared in its CI job), the FastAPI router `plugin_api.py` +
  `standalone.py`, the `avatars/` library, `fonts/`, the served data files (`features.json`,
  `inventory.json`, `panels.json`), and `chart/` — whose `files/` payload is a **committed
  projection** regenerated by `infra/scripts/sync-nexus-chart.sh`, never hand-edited. The
  `dist/` bundles are *not* chart files: they ship as the `nexus-ui-dist` ConfigMap the bootstrap
  (or `hg up`) provisions beside the release, because embedding them put the Helm release
  Secret over its 1MiB cap (#804). On the
  factory environment the chart is Pulumi-owned (`infra/src/components/nexus/index.ts`
  `NEXUS_CHART_PATH`), so a UI change deploys via `pulumi up`, not the reconcile tick. The
  frontend itself is [nexus-ui.md](nexus-ui.md)'s subject; this page stops at the unit.
- **The observability coverage inventory** — `maintainers/observability-coverage.md` (#662): one
  row per component across six dimensions (metrics, alerts, dashboards, logs, health,
  drill-down), maintained rather than one-off, with `hg observability prove` OBS011/OBS012
  gating the two router components' overlay presence. Its gap column is the honest per-component
  defect list; the systemic rows are filed (#699, #700, #701).
- **`charts/` still holds the compat trio** — `monitoring` (with its `hermes-alerting` subchart
  copy), `secret-tester`, `test-page`. These are `compat-copy` class in the boundary manifest:
  their paths are **data in persona-authored records** (`apps[].chart` is stamped verbatim into
  live Argo `path:` fields), so they exist today and are deleted only when every persona record
  stops naming them ([#672](https://github.com/factory-level/harness-hg/issues/672) collects;
  the persona fallout is tracked in the team repo).

## What does not exist yet

The in-cluster gateway for connections at the factory edge, other event providers, and the
per-component alert gaps the coverage inventory files as
[#700](https://github.com/factory-level/harness-hg/issues/700) /
[#701](https://github.com/factory-level/harness-hg/issues/701); the Nexus plugin-id rename
(`hermes-gitops` on the wire, dispositioned to
[#672](https://github.com/factory-level/harness-hg/issues/672)).

## Known defects

- `dex-sso` exposes nothing scraped, alerted, or dashboarded (#701); a dead External Secrets
  sync is silent until a pod restarts (#701); no alert fires on a dead alert path — the watcher
  is unwatched (#700). All stated per-row in `maintainers/observability-coverage.md`.
- The tunnel has no in-cluster watcher since the external-uptime cut (#647); Cloudflare-side
  analytics are the only continuous signal, with `hg edge prove` on demand.
- The `charts/` trio is a standing boundary exception the gate itself must whitelist
  (`compat-copy` with `removedBy`); the boundary is only clean once #672 lands.
