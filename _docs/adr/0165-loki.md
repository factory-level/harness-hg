# ADR 0165 — Loki: control-plane log aggregation, split by plane

2026-08-25 · executes [#661](https://github.com/factory-level/harness-hg/issues/661), part of
the final-pass epic [#646](https://github.com/factory-level/harness-hg/issues/646). Builds
on the plane convention ([ADR 0164](0164-plane-separation.md)).

## Decision

- **`control-plane/loki/chart` is hand-written and lean**: single-binary Loki (filesystem
  storage, TSDB schema, one replica, small limits) + a promtail DaemonSet + the Grafana
  datasource ConfigMap + one logs dashboard. No vendored upstream chart —
  `helm dependency update` runs nowhere here (the alerting-library precedent), and the
  upstream chart's size is exactly the #506 lesson. Images pinned in `versions.json`
  (`loki` block), asserted equal to the chart defaults by `cli/tests/versions.test.ts`.
- **Collection covers both planes, one label apart**: promtail's relabel derives
  `plane=control-plane|workload` from the namespace, using the same sets as
  `control-plane/planes.yaml` (a declared copy in `values.yaml`, kept in step). The
  shipped `hg-control-plane-logs` dashboard queries the split; the datasource uid `loki`
  is a promised constant like `prometheus`.
- **Retention is bounded and stated**: compactor-enforced, default 168h, 10Gi claim —
  a single-cluster platform, not a log warehouse.
- **Deployed via the normal GitOps path**: `bootstrap/loki.yaml` joins the seed (part 5 of
  the monitoring story), and the monitoring stack's Grafana gains the datasources sidecar
  so provisioning stays declarative. Locally, `hg up` installs it beside the other
  control-plane singletons (`ensureLoki`).
- **`hg logs` keeps the kubectl path as primary**; the Loki-backed path is Grafana Explore
  / the logs dashboard, documented rather than wrapped — a `hg logs --loki` verb is
  deliberately not built until a walkthrough needs it.

## Reason

There is no log aggregation at all; debugging is per-pod kubectl pulls and a crashed pod's
logs die with it. Loki drops into the existing Grafana/Prometheus/Alertmanager stack, and
the plane label decided in ADR 0164 is exactly what keeps control-plane and workload
streams from interleaving.

## Cost

- A hand-written chart means we own Loki's config surface: upstream schema migrations
  (TSDB versions, config renames) arrive as our maintenance, not a chart bump.
- promtail runs privileged-ish (root, hostPath /var/log/pods) on every node — the standard
  collector trade, now part of the platform's attack surface.
- promtail needs inotify headroom: on a default k3d host it crashloops with "too many open
  files" until `fs.inotify.max_user_instances` is raised (≥512; found live in this ADR's
  smoke test). The local-loop preflight should check it — filed as a follow-up.
- Single replica, filesystem storage: a node loss loses buffered chunks; retention and
  durability are explicitly best-effort at this tier.
- The live factory needs the seed changes by hand (`bootstrap/loki.yaml` + the sidecar
  block are seeded-then-operator-owned) — tracked as the factory-deploy follow-up issue,
  not silently assumed.
