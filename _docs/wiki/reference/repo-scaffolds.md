# Repository scaffolds

**What this page tells you:** what each of the three repositories contains, and who owns
each path.

| Repository | Owner | What it is |
|---|---|---|
| **Platform** | the Harness Hg maintainers | the emitter, the contracts, the charts, the CLI |
| **Destination** | the operator | the repo Argo CD watches. Mostly generated |
| **Agent Team Repo** | the team | the repo being installed. `harness-hg/` is what the platform reads |

## Platform repository

Only the user-facing parts:

```text
agent-bundle-contracts/       the frozen contracts, versioned by directory
plugin/gitops_emitter/        the emitter: renders records, scaffolds destinations
harness/eve/charts/           eve-agent, eve-bundle
infra/gitops-template/        the scaffold copied into a destination repository
infra/src/                    the Pulumi bootstrap
control-plane/                platform workloads, one chart each
cli/                          the hg CLI
nexus-ui/                     the Nexus UI source
skills/                       agent skills (npx skills add factory-level/harness-hg)
versions.json                 the one place a version pin lives
_docs/                        this manual
```

## Destination repository

Ownership is enforced by SHA-256, recorded in `bootstrap/scaffold.yaml`.

```text
bootstrap/
  project.yaml                    MANAGED   the Argo CD project and its sourceRepos allowlist
  applicationsets/*.yaml          MANAGED   one Application per record
  platform-extras.yaml            MANAGED   syncs the operator's platform/ tree
  values/cluster-values.yaml      seeded    yours after the first write
  identity.yaml, loki.yaml, …     seeded
  scaffold.yaml                   record    the ownership manifest
environment/                      YOURS     the operator's half of every concern
profiles/<name>/profile.yaml      GENERATED the record, plain Helm values
catalog/  deployments/            GENERATED by hg topology emit and hg nexus emit
platform/                         YOURS
```

| Class | Means |
|---|---|
| **MANAGED** | reconciled on every emit. Edited by you (hash differs): refused, never overwritten, and you own it from then on. Deleted by you: stays deleted |
| **seeded** | written once at scaffold time, then yours |
| **GENERATED** | data. Overwritten on every emit. Change the declaration, not the file |

Placeholder tokens (`__GITOPS_REPO_URL__`, `__CHART_REVISION__`, …) are substituted at
scaffold time. They share no characters with Argo CD's `{{ }}` on purpose.

## Agent Team Repo

**`harness-hg/` at any level is exactly what the platform reads.** The root one is the
team's; each agent carries its own. A repo with `harness-hg/team.yaml` is an Agent Team Repo.

```text
<team>/
  harness-hg/
    team.yaml              name, displayName, harnesses[]
    topology.yaml          layout, regions; no targets
    apps.yaml              shared workloads: chart, owning agent, outputs, routes
    bundles.yaml           who shares a pod
    communication.yaml     aliases and durable transport
    connections.yaml       third-party apps the team requires
    workspaces.yaml        mounts the team brings
    capabilities.yaml      requires → providers
    destination.yaml       the destination repo hg topology emit defaults to
  agents/eve/<name>/
    harness-hg/
      agent.yaml           harness, envRequires, requires, topology, deployment, gitAuthSecretRef
      backup.yaml          schedule, retention
      endpoints.yaml       endpoints[], externalInputs[], routes[]
      dashboard.yaml       the agent's card in Nexus UI
      test.yaml            dev-loop placeholders and smoke
    src/                   package.json, package-lock.json, agent/
  charts/  dashboard/  evals/
```

Every `harness-hg/*.yaml` carries `apiVersion` and `kind`. The `<name>` directory is the
agent's identity and must equal `src/package.json` `name`. The harness is read from the path
and declared again in `agent.yaml`; the two must agree.

| Path | Absent means |
|---|---|
| `harness-hg/team.yaml` | not an Agent Team Repo |
| `harness-hg/topology.yaml` | one `single` layout |
| `harness-hg/apps.yaml` | no supporting workloads |
| `harness-hg/bundles.yaml` | every agent standalone |
| `harness-hg/communication.yaml` | no aliases, no durable transport |
| `harness-hg/connections.yaml` | no third-party app bindings |
| `harness-hg/workspaces.yaml` | no mounts the team brings |
| `harness-hg/capabilities.yaml` | no team-provided capabilities |
| `harness-hg/destination.yaml` | `--output` is required on emit |
| `agents/eve/<n>/harness-hg/agent.yaml` | not an agent; the directory is skipped |
| `…/backup.yaml` | no backup routine |
| `…/endpoints.yaml` | nothing exposed, no inbound webhooks |
| `…/dashboard.yaml` | no card contribution |
| `…/test.yaml` | the built-in smoke tier only |
| `…/src/` | refused; an agent needs a payload |
| `evals/` | no platform evals |

### The operator's half

The team declares what it brings and needs. The environment spec's `grants` block declares
what the environment gives it: targets per region, DNS, policy, capabilities, extra mounts.
A name on both sides is refused, not resolved by precedence.

### Older repositories

A repository without `harness-hg/team.yaml` is read in the older one-file-per-agent layout
(`hermes-gitops.yaml` beside the payload). It keeps working. It grows no further version.

## Extension points

| You add | Path | Reaches the platform through |
|---|---|---|
| a capability request | `agent.yaml` `requires:` | the topology compiler |
| an endpoint | `endpoints.yaml` | the endpoint chart |
| a supporting workload | `harness-hg/apps.yaml` | a child Application |
| a backup routine | `backup.yaml` | a labelled CronJob |
| a dashboard | `dashboard.yaml` + `dashboard/` | `hg nexus emit` |
| behaviour tests | `evals/` | `hg eval`, never deployed |

[Declaring capabilities](../agent-team-install/declaring-capabilities.md) says what each one
does. [Agent team contract](contracts/agent-team.md) has the exact fields.
