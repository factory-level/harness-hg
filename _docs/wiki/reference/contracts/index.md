# Contract files

**What this page tells you:** every file the platform reads or writes as a contract: what it
is for, who produces it, who consumes it, and how its version behaves.

A **contract** is a file whose shape is pinned by a JSON Schema under
`agent-bundle-contracts/`. Every name below links to its generated field reference.

## Versioning

- **Contracts are versioned by directory, and a published version never changes.** Adding,
  removing or narrowing a field means a new directory. Only `description`, `title` and
  `examples` may be edited in place.
- **Generated files carry no version marker.** The consumer decides by which schema copy it
  vendored.
- **Authored files carry theirs.** Every `harness-hg/*.yaml` has `apiVersion` and `kind`. No
  file is valid under two versions.

## Generated by the platform

| Contract | Path | Produced by |
|---|---|---|
| [EveAgent record](eveagent.md) | `profiles/<name>/profile.yaml` | the emitter |

A record is plain Helm values with one `spec:` block. Its identity is its directory name.
`deployments/plan.yaml` carries an `inputsHash`; if it does not match, the tree is stale.

## Fixtures

Every version directory carries `examples/`, validated by `make schema-validate`. A fixture
named `invalid-*` must fail; everything else must pass. Cluster-values has no `invalid-*`
fixtures, so its negative paths are untested. Its frozen schema still accepts
`providers.ingress: tailscale`, which the chart refuses.
